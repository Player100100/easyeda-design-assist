## UUID 与角度约定（2026-11-14 查明）

### UUID

- `sch_PrimitiveComponent.create` 使用系统库器件身份：`libraryUuid=0819f05c4eef4c71ace90d822a990e87`、`deviceUuid=7f73bc9b909b4d519d5499acdd443b44`。
- 工程 `.epro2` 中存在独立的 DEVICE 文档 UUID `79f9c8b895d4e608`。该 DEVICE 文档的 `META.source` 为 `7f73bc9b909b4d519d5499acdd443b44|0819f05c4eef4c71ace90d822a990e87`，即系统器件 UUID 与库 UUID 的有序来源对。
- R4 的画布 getter 返回工程内 UUID `79f9c8b895d4e608`，其 `libraryUuid` 仍为 `0819f05c4eef4c71ace90d822a990e87`。因此映射可由工程源文件来源元数据核验，不能把两个 UUID 字段直接作相等比较，也不能只凭器件名称放宽校验。Symbol UUID 是另一独立标识，不参与此 Device 映射。

### 角度

- 本机 EasyEDA API `0.2.53.aee2f57a` 的 `SCH_PrimitiveComponent.create` RPC 路径将传入角度取负后发送；原理图源格式文档规定角度以度计、逆时针为正，API 读回 getter 采用源对象的画布角度。
- 本次实测符合 `expected_canvas_rotation = (-requested_api_rotation) mod 360`：API 输入 `90°`，器件回读 `270°`。因此原计划中把 `90°` 同时当作 API 请求值和回读预期值，是方案契约错误，不能据此判断 CAD 写入本身失败。
- R4 的实际引脚回读为 pin 2 在 `(1400,380)`、pin 1 在 `(1400,420)`；因此若目的是保持这次的端点次序，后续方案应明确写 `requested_api_rotation=90°`、`expected_canvas_rotation=270°`，并继续按引脚号和坐标检查方向。不得将期望值改成含糊的“角度相符”。

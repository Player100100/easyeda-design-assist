# 工作流程

## 项目级设计

复杂单板从[项目级设计框架](project-design.md)开始，按[六阶段工作指引](project-stages.md)推进：需求界定 → 架构与预算 → 模块细化与风险验证 → 集成 → 验证/使用预期确认 → 发布。允许按证据回退；简单问题可直接使用下面的局部流程。

先确定系统边界、验收标准和高影响未知，再拆职责、接口和依赖任务；不从元件堆叠开始推定功能已经闭合。项目档案保留设计意图，单项任务保留局部分析。变更前保留旧档案，用 `project-impact` 检查显式关系，再用 `project-revise` 归档；受影响项复核后记录 `review_records`。CAD 设计、外部证据及实板测量分别获取并核对版本。

PCB 工作按[PCB 设计方法](pcb-design-method.md)与[PCB playbook](playbooks/pcb.md)推进：工况/封装与板厂规则 → 机械和布局评审 → 关键回路/回流/布线 → 设计及制造包复查 → 样板验证/改版。原理图、封装、叠层、板厂工艺或机械边界改变时重开相关复核，局部问题不要求重走全流程。PCB 实际绘制和 DRC 仍在 EasyEDA 客户端完成。

## 一次建议会话

先读 `docs/agent-guide.md` 和对应 `docs/playbooks/<模式>.md`，或用 `guide --mode` 获取。轻量查询可直接回答，无需强制建档；复杂建议用任务档案保留依据。

1. **采集上下文**：读取当前工程、焦点文档、所选图元 ID 及固定字段列表内的图元属性。原理图支持元件和导线，PCB 支持元件、直线、过孔和铺铜；详情接口为 beta，每次至多读取 100 个对象。查看 `selection_details_status`、`read_errors` 与 `missing_fields`，不能把缺失字段当作不存在的设计属性。用户也可明确指定位号、网络或坐标。确认目标文档类型；多窗口时确认活动窗口。
2. **定义目标与工况**：记录要完成的设计任务，补齐关键输入，例如电压范围、负载持续/峰值电流、接口对端、信号速率、板层叠层和制造条件。未知值保持未知。
3. **划定分析范围**：用 `schematic --save` 读取一次网表，`inspect` 按位号或网络查引脚及邻居，再沿电源、驱动、反馈、保护和负载定点扩展。检查范围/截断，不按同名网合并不同板或快照。见 `docs/connectivity.md`。
4. **获取依据**：保留原手册访问能力，按具体问题用 `datasheet-search` 定位、`datasheet-page` 读完整页，必要时渲染原图核对表格/图注。记录型号、修订、页码和查询时间；标出二手资料及未知。见 `docs/datasheets.md`。
5. **分析并列建议**：分开写 CAD 事实、手册要求、计算、假设和建议。每条建议附适用条件、风险/取舍、置信度及可执行验证步骤。比较多个方案时使用同一组工况。
6. **向用户确认未决点**：数据不足且会改变结论时先询问；可继续的部分标明假设，不将假设写成事实。
7. **记录用户决定**：`accepted`、`rejected` 或 `deferred` 由用户明确表达后更新，记录理由和时间。明确要求辅助绘制时先产生方案并等待认可；认可后在方案范围内执行，不需要逐步重复确认。目标或范围变化时先修订方案。v2 器件放置已通过单器件实测；v3 实验性支持空白原理图的器件、网络标号和导线，最终逐引脚检查网表与详细 DRC，尚未实机验证。见 `docs/autodraw-policy.md`、`docs/circuit-executor.md`、`docs/live-api-verification.md`。
8. **局部复查与交接**：绘制修改后重新获取上下文，核验受影响对象。输出设计意图/决策记录及证据，供冻结版本审核使用。

## 输出建议的最低质量要求

- 器件建议写全型号、关键额定值、约束条件、封装/引脚核验状态和替代风险。
- 拓扑建议说明预期功能、关键电流/信号路径、主要器件值的推导依据、保护路径和未覆盖工况。
- PCB 建议注明信号/电源网络、层、回流参考、几何或规则依据；没有层叠/电流/制造输入时不给无条件数值结论。
- “建议增设保护”需说明被保护端口、威胁/故障、器件选型约束和保护器件到回流路径；不只列器件名。
- 不以 DRC 通过、网表一致或推荐方案常见作为设计充分性的证明。

## 与完整审核的分界

设计过程中可对局部给出快速意见，但必须记录范围和未查项。版本冻结后，完整电气/几何审核按 `epro2-辅助绘制及审核/docs/review-method.md` 执行；高风险问题由审核流程独立复核。

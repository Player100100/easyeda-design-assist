# 工作流程

原理图完成并同步 PCB 后，按[PCB 自动化契约](pcb-automation.md)选择 `full`、`partial`、`advice` 或 `layout-critical`；先保存原理图网表和完整 PCB 基线，再做范围、引脚映射、层叠和规则检查，之后输出具体布局或关键线计划。认可后可按批次调用固定 PCB 适配器；每批写后重新采集完整源和详细 DRC，当前实机写入尚需显式实验开关。

## 默认轻量循环与双模式

默认 `advice` 辅助绘制；用户明确要求协助绘制后，使用 `collaborative` 整理具体方案，再按独立的方案认可和预检执行。`component/module/board/product` 分析尺度与六类工程任务分别选择。`workflow --scope component` 可直接获得指引，无需建立档案；共享预算、供电、时序或跨板影响通过 `--signal` 提升范围，提升分析不扩大写入授权。

个人研发采用“目标与边界 → 方案与电路 → PCB 与投板 → 上电与联调 → 验证与改版”五步循环，只走问题相关步骤。旧项目六阶段状态与档案继续可用，不强制迁移。字段和命令见[首期构建说明](workflow-build.md)。

## 项目级设计

复杂单板从[项目级设计框架](project-design.md)开始，按[六阶段工作指引](project-stages.md)推进：需求界定 → 架构与预算 → 模块细化与风险验证 → 集成 → 验证/使用预期确认 → 发布。允许按证据回退；简单问题可直接使用下面的局部流程。

先确定系统边界、验收标准和高影响未知，再拆职责、接口和依赖任务；不从元件堆叠开始推定功能已经闭合。项目档案保留设计意图，单项任务保留局部分析。变更前保留旧档案，用 `project-impact` 检查显式关系，再用 `project-revise` 归档；受影响项复核后记录 `review_records`。CAD 设计、外部证据及实板测量分别获取并核对版本。

PCB 工作按[PCB 设计方法](pcb-design-method.md)与[PCB playbook](playbooks/pcb.md)推进：工况/封装与板厂规则 → 机械和布局评审 → 关键回路/回流/布线 → 设计及制造包复查 → 样板验证/改版。原理图、封装、叠层、板厂工艺或机械边界改变时重开相关复核，局部问题不要求重走全流程。PCB 实际绘制和 DRC 仍在 EasyEDA 客户端完成。

个人开发的高功率/高速板还要按专项风险标明开发者决策、板厂确认、外部测试及尚未验证的部分。开始时优先取得用途、工作/故障范围、接口对端、目标成本和可用测试条件；其他约束由 agent 查手册、读 CAD 和计算后再补问。

## 一次建议会话

先读 `docs/agent-guide.md` 和对应 `docs/playbooks/<模式>.md`，或用 `guide --mode` 获取。轻量查询可直接回答，无需强制建档；复杂建议用任务档案保留依据。

1. **采集上下文**：读取当前工程、焦点文档、所选图元 ID 及固定字段列表内的图元属性。原理图支持元件和导线，PCB 支持元件、直线、过孔和铺铜；详情接口为 beta，每次至多读取 100 个对象。查看 `selection_details_status`、`read_errors` 与 `missing_fields`，不能把缺失字段当作不存在的设计属性。用户也可明确指定位号、网络或坐标。确认目标文档类型；多窗口时确认活动窗口。
2. **定义目标与工况**：记录要完成的设计任务，补齐关键输入，例如电压范围、负载持续/峰值电流、接口对端、信号速率、板层叠层和制造条件。未知值保持未知。
3. **划定分析范围**：用 `schematic --save` 读取一次网表，`inspect` 按位号或网络查引脚及邻居，再沿电源、驱动、反馈、保护和负载定点扩展。检查范围/截断，不按同名网合并不同板或快照。见 `docs/connectivity.md`。
4. **获取依据**：保留原手册访问能力，按具体问题用 `datasheet-search` 定位、`datasheet-page` 读完整页，必要时渲染原图核对表格/图注。记录型号、修订、页码和查询时间；标出二手资料及未知。见 `docs/datasheets.md`。
5. **分析并列建议**：分开写 CAD 事实、手册要求、计算、假设和建议。每条建议附适用条件、风险/取舍、置信度及可执行验证步骤。比较多个方案时使用同一组工况。
6. **向用户确认未决点**：数据不足且会改变结论时先询问；可继续的部分标明假设，不将假设写成事实。
7. **记录用户决定**：`accepted`、`rejected` 或 `deferred` 由用户明确表达后更新，记录理由和时间。明确要求辅助绘制时先产生方案并等待认可；认可后在方案范围内执行，不需要逐步重复确认。目标或范围变化时先修订方案。v2 器件放置已通过单器件实测；v3 实验性支持器件、网络标号和导线新增，最终逐引脚检查网表与详细 DRC；历史有真实尝试与局部修复，通用端到端实机验收尚未完成。Source 属性适配器保持关闭。见 `docs/autodraw-policy.md`、`docs/circuit-executor.md`、`docs/live-api-verification.md`。
8. **局部复查与交接**：绘制修改后重新获取上下文，核验受影响对象。原理图按[绘制指引](playbooks/schematic.md)复核整页布局和变更区，分别记录视觉与电气证据。输出设计意图/决策记录及证据，供冻结版本审核使用。

持续任务可用 `new-drawing-plan --task ... --recommendation-id ... --decision-id ...` 建立明确来源，用 `drawing-trace` 查看失效项与执行结果。原任务/决策不自动覆盖；依据变化会在执行前阻断。统一 `query` 保留读取范围与缺项，多板用 `product-review` 检查显式端点及待核实记录，不按同名网跨板合并。

在非空白页新增独立模块时，先用 `capture-incremental-baseline` 采集完整源/网表/详细 DRC、全部器件及引脚几何，以 `schematic-incremental-v4` 的新方案声明编辑区域和独立网名，再走既有预检、认可与执行入口。4.1.100 三电阻闭环已实测；原有警告须逐项保留且不得新增，不能把 `verified` 理解为全页 DRC 清零或物理功能验收。明确委托自行设计并执行实验可在委托范围内继续，保留原话与具体方案；详见[增量流程](incremental-editing.md)。

局部修改前后用 `query --kind audit --save` 分别采集网表/详细 DRC，`compare-design-audits ... --save` 离线比较并保留原始输入。执行后用 `drawing-feedback` 生成独立核验动作、冻结的原建议验证项和显式依赖复核对象；已全部回读通过的执行可附 `--comparison`，工具会检查前后源绑定。稳定源及相同读数不能证明派生结果已刷新，比较不会自动关闭写后/工程验收。具体命令与状态处理见[差分与反馈](audit-and-feedback.md)。

## 输出建议的最低质量要求

接入已有网络新增支路时使用 v5，采集完整基线并声明逐线锚点。预检拒绝接触其他旧线组的目标，以及进入已核验图框保留区的编辑区域或新增支路。最后比对完整旧网表和详细 DRC。[支路流程与图框避让](branch-editing.md)

- 器件建议写全型号、关键额定值、约束条件、封装/引脚核验状态和替代风险。
- 拓扑建议说明预期功能、关键电流/信号路径、主要器件值的推导依据、保护路径和未覆盖工况。
- PCB 建议注明信号/电源网络、层、回流参考、几何或规则依据；没有层叠/电流/制造输入时不给无条件数值结论。
- “建议增设保护”需说明被保护端口、威胁/故障、器件选型约束和保护器件到回流路径；不只列器件名。
- 不以 DRC 通过、网表一致或推荐方案常见作为设计充分性的证明。

## 与完整审核的分界

设计过程中可对局部给出快速意见，但必须记录范围和未查项。版本冻结后，完整电气/几何审核按 `epro2-辅助绘制及审核/docs/review-method.md` 执行；高风险问题由审核流程独立复核。

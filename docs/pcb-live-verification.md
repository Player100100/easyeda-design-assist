## 从实机发现并修正的兼容问题

- 每次 PCB 源导出的首条 `DOCHEAD` 中 `client`、`updateTime`、`version` 会变化。保留两份原始源，设计比较只忽略这三个已观察字段；文档身份、其他文件头字段、后续记录及其顺序仍需核验。
- 最后一条 `PANELIZE` 记录可省略结尾 `|`。解析器只容许最后一条省略；中间缺分隔符继续拒绝。
- 4.1.100 Gateway 没有全局 SDK 枚举。顶层、底层、板框、多层的命名投影按本机技能文档定义并与实际层查询核对；不根据层号猜功能，未定义的内层继续拒绝。过孔/铺铜/自动布线枚举的调用仍待相应图元实机试验。
- `getCurrentPhysicalStackingConfiguration` 文档说明从4.2引入；4.1.100实测返回 `undefined`。读取记录保留不可用状态和 `stackup_available=false`。几何采集完成与层叠证据齐全分别表示；正常写入预检需要独立的层叠原件或板厂确认引用。
- 新增图元/制造导出可重编号旧记录的逻辑`ticket`；身份、内容和顺序保持时分别报告为时钟变化，不能忽略payload变化。
- 器件/属性源坐标字段实际为`x/y`；源保留4位小数，API可返回更高精度。源与API交叉核对仅容许半个末位的舍入误差；计划坐标与API只容许浮点运算误差。
- DRC实际返回分组树。比较展开为真实条目，在对象、网络、规则、错误类别和其他内容保持时，仅忽略已观察的位置与UI序号变化；未知格式仍精确比较，计数非零但条目缺失时拒绝。
- 普通通孔源类型为`NORMAL`，对应API枚举0；`POURED`归属编码为`["POURED",铜区ID]`。铜区填充路径的原始单位与位置API不同，保持原件，未据此宣称已完成几何单位校准。
- 多边形只允许闭合直线边界的起点循环或方向反转等价，其他顶点变化仍失败；板框API的空网络可返回`null`，源记录仍须无电气网络。

回归测试覆盖文件头变化、真实记录变化拒绝、最后分隔符兼容、层叠缺失时的独立证据要求，以及无全局枚举的固定脚本执行。离线通过仅证明适配逻辑，不改变上表中的PCB实机状态。

每步均先保存具体case，再执行和独立回读。板框、首个通孔和填充归属的旧检查失败经独立复核后新增`resolution.json`，没有重写原失败。铜区参数不兑现和整板布局造成断线仍属于未通过项。

整板布局后的独立位置恢复没有覆盖完整源：17器件位置和网络恢复，34条未连接基线恢复，但10条器件属性的角度由0变为-360。它们几何等价，源差异保留，不能声称源字节完全恢复。

后续仍需验证未布线板的原生布局闭环、自定义铜区参数、多层/复杂板框、差分/高速规则、真实高功率工况，以及正式认可执行入口的实机闭环。本记录只覆盖上述4.1.100工具样本，不作为通用自动布板验收。
